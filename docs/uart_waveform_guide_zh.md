# UART 仿真波形解读指南

本文说明 `uart_transactions.vcd` 怎样生成、里面有哪些关键信号、各信号代表什么，以及怎样用它证明 UART 通信正常：**电脑发给 FPGA 的数据被正确接收，FPGA 的回复被正确送回**。

每个信号都标出了推荐程度，方便挑选组会上要展示的波形。

文中的时间都取自实际仿真结果，与 `simulate_result/logs/uart_*.txt` 一致。

---

## 1. 这个仿真证明了什么

测试平台通过 `fpga_top` 的两根串口引脚（`uart_rxd` 输入，`uart_txd` 输出）与 FPGA 通信，完全模拟电脑经 USB 串口与板子的通信过程。一共进行 6 次请求/应答：

| # | 事务 | 电脑 → FPGA（请求） | FPGA → 电脑（应答） | 证明了什么 |
|---|------|---------------------|---------------------|------------|
| 1 | PING | `01` | `00 4b 59 01 07`，即 OK + `'K' 'Y'` + 版本 + 核心列表 | 最基本的收发成功 |
| 2 | WRITE_POLY | `41 00 05` + 512 字节 | `00` | 大量数据被 FPGA 接收并写入 RAM |
| 3 | READ_POLY | `40 00 05` | `00` + 512 字节 | **回传**：读回的 512 字节与第 2 步写入的完全相同 |
| 4 | KEYGEN | `10` + 32 字节种子 | `00 f3 8b 00 00` | UART 能驱动密码核心运算 |
| 5 | READ_SECRET | `50 00` | `00` + 32 字节 ρ | 回传的运算结果与 Python 计算的 SHA3-512(d‖3) 一致 |
| 6 | BAD_SLOT | `40 00 19`（slot 25 不存在） | `03`（参数错误） | 错误请求被正确拒绝，之后通信仍然正常 |

`simulate_result/logs/uart_result.txt` 的结论是 `RESULT: PASS (6/6 transactions ok)`。

其中**第 2、3 步是"发送—回传"的核心证据**：电脑发出 256 个已知的系数（0xA00、0xA01 … 0xAFF），FPGA 存下后再原样送回，逐字节一致。

## 2. 生成方法

```bash
make sim_evidence                       # 生成全部证据（NTT、Encaps、UART），约 15 秒
cd tb/evidence_uart && make             # 只生成 UART 部分，约 6 秒
```

生成的文件：

| 文件 | 内容 |
|------|------|
| `simulate_result/waves/uart_transactions.vcd` | 波形，约 11 MB，仿真时长 1.26 ms |
| `simulate_result/logs/uart_result.txt` | 6 次事务各自的检查结果，结论 PASS/FAIL |
| `simulate_result/logs/uart_transactions.txt` | 每次事务的请求/应答字节，以及在两根线上的时间段 |
| `simulate_result/logs/uart_bytes.txt` | **每个字节**的方向、数值、字符和时间（共 1,115 个字节） |

`uart_bytes.txt` 最适合用来在波形里定位：想看哪个字节，就找到它的时间，在波形中跳到那里。

> **可信度说明**：`tb/evidence_uart/evidence_uart_tb.v` 只是在**未修改的** `fpga_top` 外面包了一层，添加了把状态翻译成文字的标注信号，不改变硬件行为。

## 3. 看波形前需要知道的四件事

1. **时间单位**：VCD 用 ps，日志用 ns。日志中的 4,030 ns 对应波形中的 4,030,000 ps。时钟周期 10 ns。
2. **ASCII 显示**：名称以 `_name` 或 `_char` 结尾的信号是字符串。把显示格式设为 **ASCII**（有的工具叫 String 或 Text），才能看到 `START`、`PING`、`K` 这样的文字，否则会是一串十六进制数。
3. **仿真的波特率比板子快**：为了让仿真跑得快，这里每个串口位只占 **8 个时钟周期**，即 1 位 = 80 ns，1 个字节帧 = 800 ns。板子上是 20 MHz / 115200 ≈ 173 个时钟周期一位。**协议、帧格式和电路完全相同**，只是分频参数不同。
4. **信号在哪一层**：

   | 层次 | 内容 |
   |------|------|
   | 最顶层 `evidence_uart_tb` | 两根串口线和全部标注信号，**展示时优先从这里取** |
   | `dut` | `fpga_top` 内部连线：`rx_data`、`tx_valid`、各核心的使能信号、LED 等 |
   | `dut.u_rx` / `dut.u_tx` | 串口接收器、发送器的内部寄存器 |
   | `dut.u_host` | 协议状态机的内部寄存器 |

## 4. 关键信号一览

推荐程度：★★★ 组会必放 ／ ★★ 讲细节时用 ／ ★ 调试用。

### 4.1 串口线（物理层）

| 信号 | 位置 | 格式 | 含义 | 推荐 |
|------|------|------|------|------|
| `uart_rxd` | 顶层 | 二进制 | **电脑 → FPGA** 的串口线。空闲为 1，每个字节以一个 0（起始位）开头 | ★★★ |
| `uart_txd` | 顶层 | 二进制 | **FPGA → 电脑** 的串口线 | ★★★ |
| `txn_name` | 顶层 | ASCII | 当前是第几次事务（如 `1 PING`），由测试平台标注，方便定位 | ★★★ |

### 4.2 接收：`rx_data` 和它的使能 `rx_valid`

| 信号 | 位置 | 格式 | 含义 | 推荐 |
|------|------|------|------|------|
| `rx_bit_name` | 顶层 | ASCII | 接收器正在采样哪一位：`IDLE` / `START` / `D0`…`D7` / `STOP` | ★★★ |
| `rx_data`（= 顶层 `rx_byte`） | `dut` | 十六进制 | **接收到的数据字节**，收完一个字节后更新 | ★★★ |
| `rx_valid`（= 顶层 `rx_byte_valid`） | `dut` | 二进制 | **接收数据有效（使能）**：收完一个字节后拉高 **1 个时钟周期**，表示 `rx_data` 此刻有效，后级据此读取 | ★★★ |
| `rx_char` | 顶层 | ASCII | `rx_data` 对应的可打印字符（不可打印显示为 `.`） | ★★ |
| `rx_count` | 顶层 | 十进制 | 累计接收的字节数 | ★★ |
| `state`、`bit_idx`、`clk_cnt` | `dut.u_rx` | 十进制 | 接收状态机、位计数、位内计数 | ★ |
| `rxd_sync` | `dut.u_rx` | 二进制 | `uart_rxd` 经过两级同步后的信号，比线上晚 2 个周期 | ★ |
| `frame_err` | `dut.u_rx` | 二进制 | 停止位不是 1 时拉高（帧错误），整个仿真中应始终为 0 | ★ |

**怎么理解 `rx_data` 和 `rx_valid`**：`rx_data` 是"数据"，`rx_valid` 是"数据有效"的使能信号。只有 `rx_valid` = 1 的那个周期，`rx_data` 才代表一个新收到的字节。要在波形里读出 FPGA 收到了什么，就看每个 `rx_valid` 脉冲处的 `rx_data` 值。

### 4.3 发送：`tx_data`、`tx_valid`、`tx_ready`

| 信号 | 位置 | 格式 | 含义 | 推荐 |
|------|------|------|------|------|
| `tx_data` | `dut` | 十六进制 | 协议状态机要发送的数据字节 | ★★★ |
| `tx_valid` | `dut` | 二进制 | **发送请求（使能）**：状态机有字节要发 | ★★ |
| `tx_ready` | `dut` | 二进制 | **发送器空闲**：可以接受新字节 | ★★ |
| `tx_byte_start` | 顶层 | 二进制 | `tx_valid` 与 `tx_ready` 同时为 1 的周期（握手成功），即一个字节开始发送 | ★★★ |
| `tx_byte`、`tx_char` | 顶层 | 十六进制 / ASCII | 正在线上发送的字节及其字符 | ★★★ |
| `tx_bit_name` | 顶层 | ASCII | 发送器此刻在 `uart_txd` 上输出哪一位：`START` / `D0`…`D7` / `STOP` / `IDLE` | ★★★ |
| `tx_count` | 顶层 | 十进制 | 累计发送的字节数 | ★★ |
| `busy` | `dut.u_tx` | 二进制 | 发送器忙，是 `tx_ready` 的反相 | ★ |

**valid/ready 握手**：发送方向用的是标准握手。`tx_valid` = 1 表示"我有数据要发"，`tx_ready` = 1 表示"我能接收"，**两者同时为 1 的那个时钟沿，数据才真正被接收**。之后 `tx_ready` 变 0，直到这个字节的 10 位全部发完。

### 4.4 协议状态机（理解"请求 → 应答"的过程）

| 信号 | 位置 | 格式 | 含义 | 推荐 |
|------|------|------|------|------|
| `host_state_name` | 顶层 | ASCII | 协议状态机当前状态（见下表） | ★★★ |
| `cmd_name` | 顶层 | ASCII | 正在处理的命令（`PING`、`WRITE_POLY` …，空闲时为 `-`） | ★★★ |
| `status_name` | 顶层 | ASCII | 将要回复的状态码（`OK`、`BAD_ARG` …） | ★★ |
| `rx_cnt` | `dut.u_host` | 十进制 | 本条命令已收到的数据字节数 | ★★ |
| `p_idx`、`resp_len` | `dut.u_host` | 十进制 | 应答中正在发送第几个字节、应答总长度 | ★ |

`host_state_name` 的取值：

| 状态 | 含义 |
|------|------|
| `IDLE` | 等待命令字节 |
| `ARGS` | 接收命令参数（核心号、slot 号） |
| `EXEC` | 检查参数，决定做什么（1 个周期） |
| `WPOLY` | 接收 512 字节多项式并写入 RAM |
| `FEED` | 把收到的数据（种子等）逐字节送入密码核心 |
| `RUN` | 等待密码核心运算完成 |
| `TX_STATUS` | 发送状态字节 |
| `TX_SETUP` → `TX_WAIT1` → `TX_WAIT2` → `TX_LATCH` → `TX_SEND` | 发送一个数据字节：先给出地址，等 RAM 读出，锁存，再交给发送器 |

### 4.5 密码核心接口（各种使能信号）

这些信号在 `dut` 层，`kg_` 表示 KeyGen 核心（本测试的读写都针对它）。

| 信号 | 格式 | 含义 | 推荐 |
|------|------|------|------|
| `kg_we` | 二进制 | **RAM 写使能**：为 1 的周期，把 `host_din` 写进 `host_slot` 号多项式的 `host_addr` 位置 | ★★★ |
| `host_slot`、`host_addr`、`host_din` | 十进制 / 十六进制 | 写入/读出的 slot 号、系数下标、写入的系数值 | ★★★ |
| `kg_dout` | 十六进制 | 从 RAM 读出的系数，比 `host_addr` 晚 1 个周期 | ★★ |
| `kg_start` | 二进制 | **启动使能**：1 个周期的脉冲，启动 KeyGen | ★★★ |
| `kg_in_valid`、`kg_in_ready`、`in_data` | 二进制 / 十六进制 | 种子字节送入核心的握手：`in_data` 是数据，两者同时为 1 时被核心接收 | ★★ |
| `kg_busy` | 二进制 | 核心正在运算 | ★★★ |
| `kg_done` | 二进制 | 运算完成，1 个周期的脉冲 | ★★★ |
| `led` | 二进制 | 板上 4 个 LED：`[1]` 核心忙，`[2]` 正在处理请求，`[3]` 上次应答是错误 | ★★ |

## 5. 串口帧格式：用一个字节讲清楚

串口使用 **8N1** 格式：8 个数据位、无校验、1 个停止位。每个字节占 10 位：

```
 空闲  起始  D0  D1  D2  D3  D4  D5  D6  D7  停止  空闲
  1     0    ←—— 数据，低位（LSB）先发 ——→    1     1
```

### 例：FPGA 发送字母 `'K'`（0x4B）

`'K'` = 0x4B = 二进制 `0100 1011`。低位先发，所以 D0…D7 依次是 `1 1 0 1 0 0 1 0`。

在波形中找 **4,860 ns**（`uart_bytes.txt` 中 `TX 0x4b K` 那一行）：

| 时间 (ns) | `tx_bit_name` | `uart_txd` | 说明 |
|-----------|---------------|------------|------|
| 4,860 | `IDLE` | 1 | `tx_byte_start` 脉冲，握手成功 |
| 4,870 | `START` | **0** | 起始位 |
| 4,950 | `D0` | 1 | 0x4B 的第 0 位 = 1 |
| 5,030 | `D1` | 1 | 第 1 位 = 1 |
| 5,110 | `D2` | 0 | 第 2 位 = 0 |
| 5,190 | `D3` | 1 | 第 3 位 = 1 |
| 5,270 | `D4` | 0 | 第 4 位 = 0 |
| 5,350 | `D5` | 0 | 第 5 位 = 0 |
| 5,430 | `D6` | 1 | 第 6 位 = 1 |
| 5,510 | `D7` | 0 | 第 7 位 = 0 |
| 5,590 | `STOP` | **1** | 停止位 |
| 5,670 | `IDLE` | 1 | 下一个字节 `'Y'` 的握手 |

每位正好 80 ns（8 个时钟周期）。把 D0 到 D7 反过来读就是 `0100 1011` = 0x4B = `'K'`。**这是在波形上"手动解码"一个字节的标准方法，组会上很有说服力。**

### 例：FPGA 接收命令字节 0x01（PING）

`uart_rxd` 在 3,240 ns 变 0（起始位），3,320 ns 变 1（D0 = 1），3,400 ns 变 0（D1…D7 都是 0），3,960 ns 变 1（停止位）。

- `rx_bit_name` 显示 `START` → `D0` → … → `D7` → `STOP`，但比线上**晚约 3 个周期**。原因是接收器先经过 2 级同步，再在**每一位的中间**采样，这样可以避开位的边沿、抗干扰。
- 停止位采样完后，`rx_valid`（顶层 `rx_byte_valid`）在 **4,030 ns** 拉高 1 个周期，`rx_data` = `0x01`。FPGA 收到了这个字节。

## 6. 逐事务解读

先加 `txn_name`，缩放到整个仿真（0–1.26 ms），能看到 6 个事务依次出现。

| 事务 | 时间范围 (ns) | 波形特点 |
|------|---------------|----------|
| 1 PING | 3,240 – 8,060 | `uart_rxd` 上 1 个字节，`uart_txd` 上 5 个字节 |
| 2 WRITE_POLY | 8,450 – 421,210 | `uart_rxd` 上密集的 515 个字节，约 0.41 ms |
| 3 READ_POLY | 421,600 – 839,490 | `uart_txd` 上密集的 513 个字节 |
| 4 KEYGEN | 839,880 – 1,228,560 | 33 个字节进，**约 0.36 ms 两根线都空闲**（核心在运算），然后 5 个字节出 |
| 5 READ_SECRET | 1,228,950 – 1,257,240 | 2 个字节进，33 个字节出 |
| 6 BAD_SLOT | 1,257,630 – 1,260,800 | 3 个字节进，1 个字节出 |

### 事务 1：PING（最适合讲完整的请求—应答过程）

推荐信号：`txn_name`、`uart_rxd`、`rx_bit_name`、`rx_valid`、`rx_data`、`host_state_name`、`cmd_name`、`tx_byte_start`、`tx_byte`、`tx_char`、`tx_bit_name`、`uart_txd`

| 时间 (ns) | 事件 |
|-----------|------|
| 3,240 – 4,040 | `uart_rxd` 上传输 0x01 |
| 4,030 | `rx_valid` 脉冲，`rx_data` = 0x01 |
| 4,040 | `host_state_name`：`IDLE` → `EXEC`，`cmd_name` = `PING`，`status_name` = `OK` |
| 4,050 | `TX_STATUS`，`tx_byte_start` 脉冲，开始发送状态字节 0x00 |
| 4,060 起 | 每个字节循环一次 `TX_SETUP → TX_WAIT1 → TX_WAIT2 → TX_LATCH → TX_SEND`，在 `TX_SEND` 等待发送器空闲 |
| 4,860 / 5,670 / 6,480 / 7,290 | 依次发出 `'K'`、`'Y'`、0x01（版本）、0x07（三个核心都在） |
| 7,300 | 回到 `IDLE`，`cmd_name` 变回 `-` |

从 FPGA 收到命令到开始回复只用了 **2 个时钟周期**（4,030 → 4,050 ns）。

### 事务 2：WRITE_POLY（展示接收数据 → 写使能 → RAM）

推荐信号：`uart_rxd`、`rx_valid`、`rx_data`、`host_state_name`、`dut.u_host.rx_cnt`、`kg_we`、`host_slot`、`host_addr`、`host_din`

- 前 3 个字节 `41 00 05` 是命令、核心号（0 = KeyGen）、slot 号（5），状态依次为 `IDLE` → `ARGS` → `EXEC` → `WPOLY`。
- 之后每 2 个字节组成一个 12 位系数（低字节在前）：`00 0a` → 0xA00，`01 0a` → 0xA01 ……
- **每收到第 2 个字节，`kg_we` 就拉高 1 个周期**，把系数写入 RAM：

  | 时间 (ns) | `kg_we` | `host_addr` | `host_din` |
  |-----------|---------|-------------|------------|
  | 12,440 | 1 | 0 | 0xA00 (2560) |
  | 14,040 | 1 | 1 | 0xA01 (2561) |
  | 15,640 | 1 | 2 | 0xA02 (2562) |
  | … | … | … | … |
  | 420,440 | 1 | 255 | 0xAFF (2815) |

- 一共 256 个写使能脉冲，间隔 1,600 ns（2 个字节的时间）。`host_slot` 一直是 5。最后回复 `00`。

### 事务 3：READ_POLY（展示回传）

推荐信号：`host_state_name`、`host_addr`、`kg_dout`、`tx_byte_start`、`tx_byte`、`uart_txd`

- 状态机按 `TX_SETUP` 给出地址 → `TX_WAIT1`/`TX_WAIT2` 等 RAM 读出 → `TX_LATCH` 锁存 → `TX_SEND` 交给发送器，每个字节循环一次。
- `host_addr` 从 0 开始递增（424,020 ns 为 0，425,640 ns 为 1 …），**`kg_dout` 晚 1 个周期给出 0xA00、0xA01 ……，正是第 2 步写入的值**。
- `uart_txd` 上发出 `00`（状态），然后是 `00 0a 01 0a 02 0a …`，与第 2 步收到的字节序列完全一样。
- **展示要点**：把第 2 步开头的 `rx_data` 序列和第 3 步开头的 `tx_byte` 序列并排截图，内容一致，这就是"发送—回传"的直接证据。

### 事务 4：KEYGEN（展示 UART 驱动密码核心）

推荐信号：`host_state_name`、`kg_start`、`kg_in_valid`、`kg_in_ready`、`in_data`、`kg_busy`、`kg_done`、`led`、`uart_txd`

| 时间 (ns) | 事件 |
|-----------|------|
| 840,670 | `rx_valid` 脉冲，`rx_data` = 0x10（KEYGEN 命令） |
| 840,680 | `host_state_name` = `EXEC`，`cmd_name` = `KEYGEN` |
| 840,690 | 状态进入 `FEED`，同时 **`kg_start` 脉冲**，KeyGen 核心启动；`kg_busy` 随即变 1，`led` 的 bit 1 亮 |
| 841,470 起 | 每收到一个种子字节，`kg_in_valid` 拉高 1 个周期（`kg_in_ready` 已为 1，立即被接收），`in_data` 依次为 0x00、0x01 … 0x1F |
| 866,280 | 最后一个种子字节送入核心，状态进入 `RUN`；之后两根串口线都空闲，核心独立运算 |
| **1,224,540** | **`kg_done` 脉冲**，`kg_busy` 变 0 |
| 1,224,550 | 状态进入 `TX_STATUS`，发送应答 `00 f3 8b 00 00` |

应答中的 `f3 8b 00 00` 是小端序的 0x00008BF3 = **35,827**，即 FPGA 报告的运算周期数，从最后一个种子字节算起。

`kg_busy` 实际持续了约 38,384 个周期，比 35,827 多出的约 2,560 个周期是 32 个种子字节通过串口到达所花的时间（32 × 800 ns）。核心在接收种子期间就已经开始工作。

### 事务 5：READ_SECRET（运算结果回传）

- 应答为 `00` 加 32 字节：`5e 43 48 1c 3e eb 39 7e …`
- 与 `uart_result.txt` 中 Python 计算的 ρ = SHA3-512(d ‖ 3) 前 32 字节**逐字节相同**：

  ```
  rho (Python)  : 5e43481c3eeb397eb192505229b67a201ea893c3e2cb32da8bc342fa4dea0578
  rho (FPGA)    : 5e43481c3eeb397eb192505229b67a201ea893c3e2cb32da8bc342fa4dea0578
  ```

- 可以在波形中逐个读 `tx_byte` 与上面对照。

### 事务 6：BAD_SLOT（错误处理）

- 请求 `40 00 19` 要读 slot 25，而只有 0–19 号 slot。
- `EXEC` 状态检查参数后，`status_name` 显示 `BAD_ARG`，只回复 1 个字节 `03`，不带数据。
- `led` 变为 8（bit 3 = 错误指示灯亮）。
- 这说明错误请求不会让通信卡住：测试平台在这之后仍能正常收到应答。

## 8. 常见问题

| 问题 | 解答 |
|------|------|
| `rx_bit_name` 比 `uart_rxd` 的跳变晚几个周期 | 正常。接收器先经 2 级触发器同步（防亚稳态），再在每一位中间采样，所以显示的是接收器的视角 |
| `tx_bit_name` 与 `uart_txd` 完全对齐 | 正常。发送器直接驱动这根线，没有延迟 |
| `tx_byte` 在两个字节之间保持旧值 | 它是锁存值，表示最近一次开始发送的字节，直到下一次 `tx_byte_start` 才更新 |
| `led[0]`（心跳灯）一直不变 | 心跳灯按板上的真实时钟设计，约 1 秒闪一次，而仿真只有 1.26 ms，看不到翻转 |
| 仿真中 1 位 = 80 ns，板子上不是 | 仿真把分频系数设为 8 以加快速度；板子上 20 MHz / 115200 ≈ 173 个时钟一位。逻辑完全相同 |
| 日志里的时间在波形里找不到 | 波形单位是 ps，把 ns 乘以 1000 |
| `frame_err` 什么时候会变 1 | 停止位采样到 0 时（波特率不匹配或线路干扰）。本仿真中应始终为 0 |
| VCD 为什么有 11 MB | 包含多个每周期都变化的计数器（心跳、超时计数器等）。展示时只加本文推荐的信号即可 |
